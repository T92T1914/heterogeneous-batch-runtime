What completion means here

Inputs stay alive

The synchronous native API borrows immutable spans through return. Python snapshots exact dtype/layout inputs before releasing the GIL. External native writers still need to be excluded during that copy.

Cancellation is a request

Queued cancellation can stop a callable from starting. A running cancellation request does not interrupt its kernel or free active storage. Successful work retires its captured storage before publishing completion.

Reuse keeps resources

A fixed-shape CUDA histogram retains device arrays, a stream and events. Every call uploads current input, synchronizes and returns an independently owned host result. Explicit device arrays are limited to 64 MiB per context, excluding driver bookkeeping.

Numerical and lifetime contracts, reuse ownership, optional Python CUDA interface.

Three workloads, three verification questions
Masked reduction
Finite binary64 values selected by a byte mask. Reassociation can change rounding, so the declared numerical tolerance matters.
Tiled histogram
Exact uint64 bin counts in row-major tiles. Partial edge tiles count only real pixels.
3 by 3 stencil
Mean of each interior neighborhood, copied outer border and finite bounding at representable limits. The portable fixture tolerance is not a universal guarantee for ill-conditioned inputs.

What remains unverified

GPU diagnostics

Hardware counters were blocked by ERR_NVGPUCTRPERM. Windows Compute Sanitizer failed WDDM debugger initialization. Numerical tests and host sanitizer checks do not turn either restriction into a pass.

Other hardware

There is no HIP/ROCm or SYCL/oneAPI implementation in this source. Linux CPU execution under WSL2 is retained separately. Linux GPU, second-vendor execution and a universal CPU/GPU crossover remain unverified.

Fault and latency scope

Host-exception fixtures exercise cleanup around actual CUDA work. They do not establish actual CUDA allocation failure, device loss or recovery after a GPU reset. Small shared-host samples cannot establish extreme-tail or production latency.

The required-CUDA inference loader originally failed with Windows error 126. The automatic path was corrected using ONNX Runtime's documented preload operation. That failed initialization produced no usable output and remains part of the record.

Installed backend discovery distinguishes compiled capability from actual device execution. Required CUDA does not silently fall back to CPU.

Run or inspect the project

The numerical runtime uses CMake 3.24 or later and a C++20 compiler. Build and check CPU contracts first. A CUDA build needs a compatible toolkit and actual device architecture. The optional classifier has its own dependency and model acquisition instructions.

# The SYCL backend

The optional SYCL backend is built with the DPC++ compiler for NVIDIA hardware. It selects a GPU, reports it and runs all three workloads of the repository: the tiled histogram, the masked reduction and the 3 by 3 stencil, each with executed correctness and lifecycle tests on an RTX 4090. The [backend discovery contract](backend-discovery.md) covers the installed `sycl` component, and the [open gates page](limits.md#a-second-gpu-vendor) explains why this backend does not close the second vendor gate.

## Build

The backend is built and tested only on Linux with DPC++. Configure the whole project with that compiler, because CMake uses one C++ compiler for every target. `-fsycl` is applied to the SYCL library alone, and the other targets compile as ordinary C++. The linker and the tests need the DPC++ runtime libraries, so put them on the loader path first.

```sh
export LD_LIBRARY_PATH=<dpcpp>/lib:$LD_LIBRARY_PATH
cmake -S . -B build/sycl -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=<dpcpp>/bin/clang++ \
  -DHBR_SYCL=ON -DHBR_SYCL_FLAGS=--cuda-path=<cuda-toolkit>
cmake --build build/sycl --parallel 2
ctest --test-dir build/sycl --output-on-failure
```

`HBR_SYCL_TARGETS` sets `-fsycl-targets` and defaults to `nvidia_gpu_sm_89`, which compiles the device code ahead of time for an RTX 4090. `HBR_SYCL_FLAGS` adds options to both compiling and linking, such as the CUDA toolkit path that the NVIDIA target needs for `ptxas` and libdevice. CMake drops a repeated option from such a list, so an option that must repeat, like `-Xsycl-target-backend`, needs the `SHELL:` prefix. Windows is refused at configure time, because the DPC++ Windows release has no CUDA adapter and nothing here was built there.

`hbr::hbr_sycl` is a shared library, so it carries its own device image, and `hbr/sycl.hpp` includes no SYCL header. An application compiled by g++ or any other C++20 compiler links it with no SYCL compiler, as long as the DPC++ runtime libraries are on the loader path.

## Device selection

`hbr::sycl_device()` selects a GPU with the SYCL GPU selector, which honors `ONEAPI_DEVICE_SELECTOR`, and reports its backend, platform, name, driver, memory and its `fp64` and `atomic64` aspects. It considers only GPUs that can run every kernel the library carries, so on a host with GPUs from more than one backend it skips one this NVIDIA build has no device image for, and one that lacks an aspect a kernel needs. That skip follows from the code and the SYCL specification. It has not run on a host with GPUs from more than one backend. The kernels together need the `fp64` and `atomic64` aspects, so a selected GPU always reports both. It never selects a CPU device. A SYCL error leaves the library only as `std::runtime_error`, so an application that includes no SYCL header can still catch it.

## Tiled histogram

`hbr::sycl_tile_histogram(image, rows, cols, tile_rows, tile_cols, local_bins)` is the counterpart of `hbr::cuda_tile_histogram`. It returns 256 exact `uint64` counts for each tile, tiles in row order, with the partial tiles at the right and bottom edges counted like whole ones. One work group of 256 work items counts each tile. With `local_bins`, the default, it counts into work group local bins and copies them out once. Without it, it counts with atomics straight into that tile's output. Both need the `atomic64` aspect, so the selector skips a GPU without it.

Zero tile dimensions and a shape that does not match the image throw `std::invalid_argument`, and a tile grid of more than 8,388,607 tiles throws `std::overflow_error`, all before a device is selected. That limit comes from DPC++, which by default requires a kernel's global range to fit in `int`, and each tile takes 256 work items. `hbr::cuda_tile_histogram` accepts larger grids. An empty image returns an empty result without selecting one. Each call is a completed synchronous call on its own in order queue. The input is borrowed until the call returns. Every queued copy and kernel has finished before the call returns or throws, device memory is freed only after that, and the result owns its storage. An asynchronous SYCL error is kept and thrown after the queue has drained, as `std::runtime_error` like every other SYCL error.

## Masked reduction

`hbr::sycl_masked_reduce(values, mask)` is the counterpart of `hbr::cuda_masked_reduce`. It returns the binary64 sum of the values whose mask byte is nonzero. The first pass runs at most 4096 work groups of 256 work items. Each work item sums the selected values on a grid stride, and each work group adds its 256 lanes in a fixed tree and writes one partial sum. A second pass with one work group and no mask adds the partial sums the same way. It needs the `fp64` aspect, so the selector skips a GPU without it.

A size mismatch and a nonfinite value, selected or not, throw `std::invalid_argument`. A selected absolute sum beyond the binary64 range throws `std::overflow_error`, through the same check `hbr::masked_reduce` uses. All of these happen before a device is selected, and an empty input returns 0 without one. The completed call contract is the histogram's. The summation order differs from the CPU, so the sum can differ from the scalar result in its last bits. When every partial sum is exact in binary64, as with small integers, the sums are equal. The range check bounds the selected sum in sequential order, so within a few ulps of the largest binary64 value a sum in the device's order could still round to infinity, as on the CUDA path.

## Stencil

`hbr::sycl_stencil3x3(image, rows, cols)` is the counterpart of `hbr::cuda_stencil3x3` and `hbr::stencil3x3`. Each work item handles pixels on a grid stride over at most 4096 work groups of 256 work items. A border pixel, and every pixel of an image under 3 in either dimension, is copied. An interior pixel is the sum of its nine neighbors, each divided by nine, added in the order the scalar loop uses, and bounded to the largest finite magnitude because the last rounded addition can overflow at the limit. The library is compiled with `-ffp-contract=off`, like the CPU library on Linux. It needs the `fp64` aspect, so the selector skips a GPU without it.

A shape that does not match the image and a nonfinite value throw `std::invalid_argument`, and a shape whose product overflows throws `std::overflow_error`, before a device is selected. An empty image returns an empty result without one. The completed call contract is the histogram's.

The [numerical contract](contracts.md) allows the stencil an error of `1e-13` against an independent oracle, and the CUDA test allows `1e-12` against the scalar result. The SYCL test asks for more, every output equal to the scalar one bit for bit with the sign of zero included, and on this toolchain and card it passed. That is a result of these runs, not a promise for other compilers or devices.

All three operations are correctness and lifecycle ports. They measure no time and make no performance claim.

## Tests

Tests whose names start with `sycl_` need a SYCL GPU. `sycl_device` checks the report. `sycl_histogram` compares 60 cases with the scalar reference, in both bin modes: the shapes of the CUDA histogram test and 32, 256 and 1024 square images in 64 by 64 tiles with spread and skewed values. It also checks the rejections, that the input is left unchanged and that results own their storage, eight concurrent jobs through a `Runtime` with two workers, and both kinds of cancellation. Cancelling a running job stays a request and the job still completes correctly, while cancelling a queued one is confirmed and it never runs. `sycl_reduction` compares 24 cases with the scalar reference within 1e-9, using the shapes and inputs of the CUDA reduction test, of which 15 reach the device and 9 are empty, and 16 cases of small integers for equality, up to 3,000,001 values so that each work item strides several times. It checks the same rejections, ownership, runtime concurrency and cancellation as the histogram test, and that an unselected value never counts toward the range check. `sycl_stencil` compares bit patterns with the scalar result, so the sign of zero counts, in 31 cases: the 24 shapes and inputs of the CUDA stencil test, 1024 by 1024, 2049 by 1023 and 3 by 1,000,003 images of spread values, constant images at both ends of the binary64 range, where the bound applies, an image of subnormal values and a constant image of the smallest negative subnormal, whose interior is -0.0. It checks the same rejections, ownership, runtime concurrency and cancellation. `sycl_faults` compiles the library again with test checkpoints, from the allocations to the final wait, six in the histogram, eight in the reduction and six in the stencil. It fails at each one, for the histogram in each bin mode, once with a host exception and once with a `sycl::exception`, which must arrive as `std::runtime_error` with the `SYCL: ` prefix. It then leaves an asynchronous SYCL error for completion to find, as the queue's handler would, and that error must be thrown after the drain. Every time the queue must drain without an error, no device allocation may remain and the next call must be correct. The handler itself never runs in these tests, because no real device error occurs. `host_sycl_selection` hides every GPU with `ONEAPI_DEVICE_SELECTOR=*:cpu`, so it runs on any host. There all three operations must still reject bad input, as `std::invalid_argument` or `std::overflow_error`, including an oversized tile grid and a selected sum beyond the binary64 range, and return an empty result or 0 for empty input, while real input and the device query must fail with `std::runtime_error`. On a host with no GPU at all it shows only that the error is converted, not that the selector setting is honored.

The hosted [`SYCL compile`](../.github/workflows/sycl-compile.yml) workflow fetches the DPC++ 7.2.0 release and the CUDA 13.2.2 device tools by SHA-256, builds the backend for `sm_89` and checks that the library carries that device image. It then runs every test whose name does not start with `sycl_`, followed by the installed discovery check with `--sycl-built`. It executes nothing on a device.

## Timing comparison

`hbr_sycl_cuda_bench` times the complete CUDA and SYCL calls of the three workloads in one process, interleaved at one host clock boundary, under the protocol in [`sycl-cuda-protocol.json`](sycl-cuda-protocol.json). That protocol was committed before any sample, and it names what each complete call includes. I amended it on November 23, 2026, also before any sample, because the usual load of this working desktop never let the card fall under the 10 percent utilization the first version required, even with no game running. The run now goes ahead at the usual load of this working desktop. Each workload runs as a CUDA call and a SYCL call back to back, CUDA first in even iterations and SYCL first in odd ones, 121 times for each image size. Before every call, outside the timed span, the benchmark reads the card's utilization and memory through NVML, which it opens at run time. A pause of two seconds before each image size and after the last one gives an idle reading of the desktop load alone. Every published result carries the label of a working desktop, with that load stated beside it. The target is built only when `HBR_CUDA` and `HBR_SYCL` are both on. The configure line above then also needs `-DHBR_CUDA=ON`, nvcc as `CMAKE_CUDA_COMPILER`, a host compiler for nvcc such as `g++` in `CMAKE_CUDA_HOST_COMPILER`, since the C++ compiler is DPC++, and `-DCMAKE_CUDA_ARCHITECTURES=89`. nvcc looks for its libraries in `lib64`, so a toolkit assembled from NVIDIA's redistributable archives, which put them in `lib`, needs a `lib64` link to `lib`, as the workflow makes. `--plan` prints the plan and `--sequence` prints the order of every run row, both without touching a device, and the hosted `SYCL compile` workflow checks the plan against the protocol and the order against the one the report expects. `--verify` runs each condition once against the scalar reference, says whether the two backends gave the same bits and prints no time. `tools/run_sycl_cuda.py` runs it once in the WSL distro from Windows and writes the samples with a receipt. It runs nothing unless the build was configured from the same checkout and ninja has no work left in it, and it stops the benchmark inside the distro at the protocol's time limit. It refuses to write over an earlier attempt and marks a run passed only when the benchmark exited 0, the source did not move and the person who started it confirmed that no game was running. `tools/report_sycl_cuda.py` checks the order, transfer bytes, timing fields and histogram counts of every row against the protocol and puts the CUDA and SYCL medians side by side, with the median of the ratios within each pair and the load the readings show. The reduction and stencil values are checked against the scalar reference by the benchmark itself, which exits with an error on a mismatch. No timing sample has been taken yet.
